# v0.134.0 - Performance, Scale, and True Streaming Qualification

**Status:** Released

**Incremental effort:** 3-5 person-weeks for the streaming scope

**Goal:** Complete the HTTP query-delivery contract while qualifying the existing performance and scale work. Large SPARQL results must flow incrementally from PostgreSQL to the client with bounded memory, network backpressure, deadlines, cancellation, standards-valid encoding, and clean connection reuse.

## Deliverables

- [x] **STREAM-01 - Typed result contract:** add internal query metadata and typed RDF binding rows so buffered and streaming formatters preserve IRIs, blank nodes, datatypes, language tags, unbound variables, and empty-result headers identically.
- [x] **STREAM-02 - Direct row streaming:** replace streaming-path `tokio_postgres::Client::query()` calls with `query_raw()`/`RowStream`; the HTTP body must poll the database row stream directly without a detached producer or unbounded channel.
- [x] **STREAM-03 - Standards-valid encoders:** stream SPARQL Results JSON, CSV, TSV, and N-Triples with bounded chunk coalescing; advertise NDJSON only as `application/x-ndjson`; keep XML, Turtle, and JSON-LD buffered behind existing row and byte limits.
- [x] **STREAM-04 - Backpressure and lifecycle:** use one checked-out connection and read-only transaction per stream, enforce statement and idle timeouts, cancel PostgreSQL work on disconnect or deadline, roll back on failure, and discard any connection whose session cleanliness cannot be proven.
- [x] **STREAM-05 - One HTTP path:** use the same execution pipeline for streaming-safe responses from `/sparql` and the compatibility alias `/sparql/stream`, including authentication, authorization, rate limits, tracing, replica routing, and errors.
- [x] **STREAM-06 - Observability:** record active streams, rows, bytes, duration, first-byte latency, cancellation reasons and failures, database and encoder errors, and connection discards; wire extension cursor/page counters to real emission.
- [x] **STREAM-07 - Evidence and docs:** publish current first-byte, throughput, peak-memory, cancellation-latency, slow-client, format, and 1/10/100/500-concurrent-stream evidence with exact hardware and dataset metadata.

The existing keyset-pagination, variable-predicate bounding, benchmark-environment, workload-tier, and regression-gate scope remains release-blocking.

## Required Blocking Checks

| Check | Required evidence |
|---|---|
| `http-stream-format` | Independent parsers accept complete JSON, CSV, TSV, and N-Triples output, including empty results and all RDF term forms. |
| `http-stream-first-byte` | A deliberately slow query emits its first result before the full query completes. |
| `http-stream-memory` | At least one million rows stream within the accepted fixed RSS envelope. |
| `http-stream-slow-client` | Throttled readers apply backpressure without unbounded server buffering. |
| `http-stream-disconnect-cancel` | Dropping the response removes the backend query from `pg_stat_activity` within the accepted cancellation interval. |
| `http-stream-timeout` | Deadlines cancel local and replica-routed queries and classify the cancellation correctly. |
| `http-stream-pool-reuse` | The next request receives a clean connection with no open transaction or leaked session setting. |
| `regress-v0134-streaming` | Extension metadata, typed values, cursor pages, row counters, and large-result iteration pass pg_regress coverage. |
| `benchmark-streaming` | First-byte, throughput, peak HTTP/backend memory, cancellation latency, format, slow-client, and concurrency results are attached to release evidence. |

Encoder unit tests must cover zero, one, and many rows; every RDF term form; unbound values; Unicode and control characters; escaping; and errors before and after body emission. HTTP integration tests must also cover ASK, SELECT, CONSTRUCT, DESCRIBE, replica routing, graceful shutdown, and connection cleanup.

No required check may skip successfully, use `continue-on-error`, or omit its result count and evidence artifact.

## Exit Criteria

- No streaming-safe format buffers the full PostgreSQL result.
- Peak memory remains bounded as result cardinality increases.
- Slow clients apply backpressure, and disconnects and deadlines cancel PostgreSQL work.
- Connections return to the pool only after commit or rollback and session cleanup.
- Streaming outputs pass independent parsers and preserve typed RDF terms.
- Required blocking checks and the existing v0.134 performance gates pass with current raw evidence.
