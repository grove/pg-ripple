# v0.132.0 — Conformance, feature truth, and release evidence

**Status: Released ✅** | **Scope: Large**

## Objective

Make every public capability claim traceable to immutable, executable evidence.

## Delivered

- [x] Add `tests/conformance/sources.lock` with immutable corpus metadata,
  archive checksums, shape bounds, and license information.
- [x] Make required conformance suites fail on missing data, empty runs,
  unexpected counts, failures, timeouts, and XPASS results.
- [x] Validate structured known-failure entries with issue, owner, rationale,
  and expiry fields.
- [x] Add versioned conformance reports with release, commit, corpus, timing,
  and unexpected-failure metadata.
- [x] Generate and validate `results/features/<version>/feature-evidence.json`
  from the `feature_status()` catalog and repository evidence paths.
- [x] Compare the central HTTP router registry with documentation and the
  checked-in/runtime OpenAPI specification, including access classifications.
- [x] Add `scripts/build_release_evidence.py` for provenance, migrations,
  conformance, feature, security, benchmark, test-count, SBOM, and checksum
  evidence.
- [x] Bound variable-predicate UNION expansion with
  `pg_ripple.max_predicate_union_branches`.
- [x] Replace export OFFSET pagination with statement-id keyset pagination and
  add the required rare, delta, and main indexes.
- [x] Add the 72-hour soak harness and external-audit engagement brief for the
  v1.0.0 readiness gate.
