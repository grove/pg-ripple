# v0.129.0 — A18 Critical & High Correctness Remediation: JSON Writeback Bug Fixes

## Theme

Repair the JSON-mapping relational writeback feature (v0.128.0
JSON-WRITEBACK-01) so that `enable_json_writeback()` actually means what it
says. A wrong dictionary column name made the async trigger-based path
silently non-functional from day one; v0.128.1 shipped an emergency
containment patch that failed closed instead of lying about coverage, but
that made the underlying bug unfixable-around — `enable_json_writeback()`
could no longer succeed at all. This release fixes the root cause and closes
the enqueue-coverage gap that made success depend on a predicate already
being promoted to its own VP table.

## Motivation

[plans/PLAN_OVERALL_ASSESSMENT-18.md](PLAN_OVERALL_ASSESSMENT-18.md) scored
v0.128.0 at 4.15/5.0 and flagged one Critical and one High finding in the
writeback path:

- **C18-01**: `enable_json_writeback_impl()` and
  `drain_json_writeback_queue()` queried `_pg_ripple.dictionary.iri`, a
  column that has never existed (the real column is `value`, disambiguated
  by `kind`). Every predicate lookup failed, and the failure was swallowed
  into "not yet covered" rather than surfaced as an error.
- **H18-02**: direct writeback (`writeback_json_row()` /
  `writeback_json_row_delete()`) returned a hard-coded row count, cast every
  value to `::text` (breaking non-text columns), and could build a
  mis-numbered SQL statement when a configured key column had no value.

## Deliverables

### C18-01 — Async writeback correctness

- [x] `enable_json_writeback_impl()` / `drain_json_writeback_queue()` query
  `_pg_ripple.dictionary` via `WHERE value = $1 AND kind = KIND_IRI` (lookup)
  and `SELECT value ... WHERE id = $1 AND kind = KIND_IRI` (decode) instead
  of the nonexistent `iri` column
- [x] Predicate-lookup SPI errors are fatal (`pgrx::error!`) rather than
  being folded into the "uncovered" bucket via `.unwrap_or(None)`
- [x] `json_writeback_enqueue_fn()` gains an optional second trigger
  argument (a predicate-id filter) so it can be installed on `vp_rare`,
  which is shared across every not-yet-promoted predicate
- [x] `json_writeback_enqueue_fn()` treats an `INSERT` on a `*_tombstones`
  table as a `delete` event, covering main-resident deletes
- [x] `enable_json_writeback()` installs a predicate-filtered trigger on
  `vp_rare` for every mapped predicate (covering the pre-promotion window)
  in addition to the dedicated delta/tombstone triggers when a predicate is
  already promoted — a predicate no longer needs to be promoted for
  `enable_json_writeback()` to succeed
- [x] `promote_predicate()` calls
  `json_mapping::install_writeback_triggers_after_promotion()` right after
  creating a predicate's dedicated tables, installing delta + tombstone
  triggers for every mapping already covering that predicate
- [x] `disable_json_writeback_impl()` trigger discovery rewritten to query
  `pg_catalog.pg_trigger` directly via a single-row `string_agg` fetch — an
  `information_schema.triggers` / multi-row `Spi::connect` query was found
  to return zero rows for triggers created moments earlier by another SPI
  call in the same session, silently leaving triggers un-droppable
- [x] `sql/pg_ripple--0.127.0--0.128.0.sql` backfilled with the
  `json_writeback_enqueue_fn()` DDL it was missing — databases that upgraded
  via `ALTER EXTENSION` (rather than a fresh `CREATE EXTENSION`) never got
  the function `enable_json_writeback()` requires

### H18-02 — Direct writeback correctness

- [x] `writeback_json_row()` / `writeback_json_row_delete()` report the real
  affected-row count via `INSERT ... RETURNING 1` / `DELETE ... RETURNING 1`
  wrapped in a `SELECT count(*) FROM cte`, instead of a hard-coded `1`
- [x] Values are cast with `CAST($n AS <pg_type>)` using a column-type map
  derived from `pg_attribute` and cached in the new
  `_pg_ripple.json_mappings.writeback_column_casts` column, instead of a
  blanket `::text` that fails for non-text columns
- [x] `writeback_key_columns` are validated up front
  (`require_key_columns_present()`); a missing value raises `PT0552`
  instead of building a placeholder list where bound values and `$n`
  references fall out of sync
- [x] `tests/pg_regress/sql/v0128_json_writeback.sql`: fixed the `'skip'`
  conflict-policy expected output (0 rows, not 1); added JWB-23–28 covering
  an integer primary key, a UUID key column, a zero-row delete, a missing
  key-column error, the `'error'` conflict policy, and
  `enable_json_writeback()` succeeding for a still-rare predicate

### L18-02 — Queue-drain error handling

- [x] `drain_json_writeback_queue()`'s status-update `UPDATE` failures are
  logged via `pgrx::warning!` and increment
  `pg_ripple_json_writeback_drain_errors_total` (new counter, exposed via
  `streaming_metrics()` and the `pg_ripple_http` `/metrics` endpoint),
  leaving the row pending with `retry_count` incremented instead of the
  previous `let _ = ...` silent-drop pattern
- [x] New `_pg_ripple.json_writeback_queue.retry_count SMALLINT` column

### Migration

- [x] `sql/pg_ripple--0.128.1--0.129.0.sql` — `retry_count` column,
  `writeback_column_casts` column, updated `json_writeback_enqueue_fn()`
- [x] `sql/pg_ripple--0.127.0--0.128.0.sql` backfilled (see C18-01 above)
- [x] Verified manually on an incrementally-upgraded database
  (`CREATE EXTENSION ... VERSION '0.128.1'` → `ALTER EXTENSION ... UPDATE TO
  '0.129.0'`): direct writeback, `enable_json_writeback()`, and automatic
  enqueue all work without a fresh install

## Exit Criteria

- All pg_regress tests in `tests/pg_regress/sql/v0128_json_writeback.sql`
  pass on PG18, including the six new H18-02 cases and the ENQUEUE-COVERAGE
  positive-path case (JWB-28)
- `enable_json_writeback()` succeeds for a predicate that has been ingested
  but not yet promoted to its own VP table
- `disable_json_writeback()` verifiably drops every trigger it installed
  (confirmed via direct `pg_catalog.pg_trigger` inspection, not just absence
  of an error)
- A database upgraded via `ALTER EXTENSION` from any pre-0.129.0 version has
  a fully working `enable_json_writeback()` — no `function does not exist`
- Full pg_regress suite passes with zero regressions (295/295)
- `cargo fmt --all -- --check` passes
- `cargo clippy --features pg18 -- -D warnings` introduces no new warnings
- `bash tests/test_migration_chain.sh` passes
