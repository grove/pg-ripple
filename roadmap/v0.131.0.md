# v0.131.0 — Security hardening and conformance evidence

## Objective

Make accidental insecure HTTP deployment explicit and make conformance results
traceable to the version that produced them.

## Deliverables

- [x] Make HTTP authentication fail closed when no token is configured, with an
  explicit development-only unauthenticated override and startup warning.
- [x] Escape temporal snapshot and diff RDF terms with one shared N-Quads
  formatter, including IRIs, literals, blank nodes, language tags, and datatypes.
- [x] Make required W3C and Jena data-fetch steps fatal and preserve explicit
  skip evidence for informational suites.
- [x] Refresh compatibility rows for v0.124.x through v0.128.x and correct the
  HTTP companion configuration documentation.
- [x] Reject raw values in `pg_ripple.llm_api_key_env`, with a superuser-only
  migration escape hatch.
- [x] Parse and enforce `PG_RIPPLE_HTTP_TRUST_PROXY` as a validated CIDR list.
- [x] Stamp conformance artifacts with their release version and generation time,
  publish them under a versioned results directory, and mark historical reports.
- [x] Add the `0.130.0 → 0.131.0` extension migration script.

The production-readiness scope for this release is also complete:

- [x] Load typed HTTP configuration once at startup, including `_FILE`
  secrets, loopback binding defaults, mode validation, and PostgreSQL TLS
  (`disable`, `require`, `verify-ca`, and `verify-full`).
- [x] Apply a central route-access registry for public health, read, write,
  admin, and metrics classes, with cross-class negative tests.
- [x] Provide the least-privilege `pg_ripple_http` role script without direct
  `_pg_ripple` schema grants.
- [x] Add hardened Docker/Helm defaults: pinned base images and Git commits,
  non-root/read-only HTTP sidecar security context, explicit development mode,
  and an optional NetworkPolicy.
- [x] Apply one bounded, DNS-validated, redirect-disabled outbound policy to
  HTTP rule-library fetches, with operator allowlists and port controls.
- [x] Redact DSNs, passwords, tokens, and authorization values from diagnostics
  and startup logs.
