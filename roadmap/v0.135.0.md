# v0.135.0 - Safe Application Query API and Compatibility Freeze

**Status:** Released

**Incremental effort:** 3-5 person-weeks for typed bindings and registered-prefix mode

**Goal:** Freeze a v1 query interface that lets applications supply RDF values without constructing SPARQL text and optionally use the existing governed prefix registry without weakening strict SPARQL behavior.

## Deliverables

- [x] **BIND-01 - Typed binding contract:** accept one JSON object of URI and literal initial bindings; reject malformed variables, unknown fields, nulls, blank nodes, RDF-star terms, oversized values, and too many bindings with stable PT0570-PT0579 errors.
- [x] **BIND-02 - Algebra-level semantics:** apply bindings after parsing as a programmatically constructed one-row solution mapping; never use textual substitution, regex replacement, or query-string concatenation.
- [x] **BIND-03 - SQL parameters and cache reuse:** dictionary-encode bound RDF terms and pass typed SQL parameters; key plans by query structure, binding names/types, prefix mode/generation, schema generation, and relevant GUCs, never by values.
- [x] **BIND-04 - Compatible public overloads:** add binding overloads for `sparql()`, `sparql_construct()`, `sparql_describe()`, and `sparql_cursor()` while preserving existing signatures; reject parameterized SPARQL Update explicitly.
- [x] **PREFIX-01 - Governed existing registry:** harden `_pg_ripple.prefixes` with ownership, timestamps, mutation privileges, validation, and transactional generation state; do not create a parallel registry.
- [x] **PREFIX-02 - Explicit query mode:** add `pg_ripple.sparql_prefix_mode = strict|registered`, defaulting to `strict`; query-local declarations win, registered declarations are deterministic, and prefix changes invalidate only registered-mode plans after commit.
- [x] **BIND-05 - HTTP bindings route:** add authenticated `POST /sparql/bindings`; use the existing authorization, replica, and format-negotiation paths.
- [x] **API-01 - Freeze and migrate:** include the v0.135 public overloads, route, GUCs, errors, schemas, strict-default policy, and schema decision in `api/stable-v1.json`; preserve existing prefixes through `sql/pg_ripple--0.134.0--0.135.0.sql`.

The existing public-schema decision, stable SQL/HTTP/GUC/error manifest, deprecation contract, and feature-profile scope remains release-blocking.

## Required Blocking Checks

| Check | Required evidence |
|---|---|
| `regress-v0135-bindings` | Binding parser and algebra semantics pass across all supported query forms and operators. |
| `regress-v0135-prefix-mode` | Strict default, registered resolution, local override, validation, permissions, and transactional generation pass. |
| `http-bindings` | JSON/CSV/TSV and N-Triples responses use v0.134 streaming, cancellation, timeouts, auth, and replica routing. |
| `bindings-plan-cache` | One query shape with 100 values produces one compilation miss followed by value-correct cache hits. |
| `prefix-cache-invalidation` | Committed changes invalidate registered plans; rolled-back changes alter neither generation nor cache behavior. |
| `bindings-security-negative` | Binding and prefix payloads cannot alter SPARQL, generated SQL, prologue structure, or internal catalogs. |
| `bindings-fuzz-smoke` | Binding JSON fuzzing never panics, emits malformed SQL, or treats values as syntax. |
| `prefix-fuzz-smoke` | Prologue fuzzing changes only missing declarations and never overwrites local prefixes. |
| `api-stability-manifest` | The complete public surface matches the checked-in v1 manifest. |
| `migration-0134-to-0135` | Existing prefix rows, ownership, grants, generation, functions, and overloads survive upgrade. |
| `fresh-vs-upgrade-0135` | Fresh and upgraded installations have equivalent schemas, privileges, functions, GUCs, and behavior. |

Unit and regression matrices must cover URI and every supported literal form; subject, predicate, and object bindings; FILTER, OPTIONAL, UNION, MINUS, VALUES, BIND, subqueries, aggregation/HAVING, property paths, named graphs, SERVICE policy, ASK, CONSTRUCT, DESCRIBE, empty results, and projection of a bound variable.

No required check may skip successfully, use `continue-on-error`, or omit its assertion count and evidence artifact.

## Exit Criteria

- No binding value is inserted into SPARQL or SQL text.
- Binding semantics and plan reuse pass the positive, negative, and fuzz matrices.
- Strict prefix mode remains the default; registered mode is deterministic, permission-controlled, transactional, and cache-safe.
- Local declarations override registry entries.
- The HTTP route inherits v0.134 streaming and cancellation behavior.
- Fresh installs and upgrades are equivalent.
- Every public addition appears in `api/stable-v1.json`, and RC0 begins the API freeze.
