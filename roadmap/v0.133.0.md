# v0.133.0 — Crash recovery, backup, failover, and operations

v0.133.0 turns the existing recovery smoke tests into a release qualification
surface. It adds deterministic, non-production fault points; a stable
`pg_ripple.health()` report; crash, backup, PITR, promotion, and resource
pressure harnesses; and operator runbooks.

## Delivered

- Test-only fault injection supports delay, transaction error, simulated SPI
  failure, and process termination at the storage, inference, writeback, and
  worker boundaries.
- Crash recovery scripts validate committed counts/checksums, queue unlocks,
  worker state, and replay safety after PostgreSQL restart.
- Backup and failover qualification scripts cover logical dump/restore,
  physical base backup, PITR configuration, standby promotion, and replica
  write protection when the required PostgreSQL tools are available.
- `pg_ripple.health()` reports extension/schema version, migration state,
  workers, merge backlog, cache, dead letters, and replication diagnostics.
- Runbooks document each failure mode under `docs/src/operations/`.
